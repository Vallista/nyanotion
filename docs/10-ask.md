# 10 — 문서에 물어보기 (M6)

> "작년에 정리한 김장 레시피 뭐였지"에 **근거 링크와 함께** 답한다.
> 그리고 **다른 가족 구성원의 비공개 문서는 절대 근거에 안 나온다.**

두 번째 문장이 첫 번째보다 중요하다. 잘 찾는 검색이 남의 일기를 물어 오면 이 앱은 집에서 쫓겨난다.

---

## 길

```
저장  ──▶ ai_job 에 "할 일" 만 적는다 (즉시 끝)
              │
              ▼
          apps/worker  ── 한가할 때 가져간다
              │  토막 내기 → 바뀐 것만 임베딩 → document_chunk
              ▼
질문  ──▶ readableDocumentIds  ──▶ 하이브리드 검색(RRF)  ──▶ 근거 → 모델 → 답
```

---

## 왜 저장할 때 바로 임베딩하지 않는가

이 집의 GPU 는 게임도 돌린다 (`ARCHITECTURE.md` §9). 저장 경로에서 임베딩하면

- 타자를 치는 동안 저장이 몇 초씩 걸리고,
- 게임 중에는 **저장 자체가 실패한다.**

그래서 저장은 `ai_job` 에 줄 하나를 적고 끝낸다. 디바운스는 **부분 유니크 색인**이 한다 —
대기 중(`state = 'queued'`)인 같은 종류의 일은 문서당 하나뿐이고, 새 저장은 `run_after` 만 미룬다.
스무 번 저장해도 편집이 멈춘 뒤 한 번 돈다.

게임 중이면 워커가 일을 **되돌려 놓고** 쉰다 (`requeueJob`). 시도 횟수를 늘리지 않으므로 포기하지 않는다 —
이건 그 일의 잘못이 아니다.

## pgvector 는 있으면 쓰고 없으면 없이 돈다

`CREATE EXTENSION vector` 는 **슈퍼유저만** 할 수 있다. 그래서 새 컴퓨터, CI, 백업 복구 직후에는
없을 수 있다. 그때 문서 질의가 아예 안 되면 안 된다.

| | 임베딩 원본 | 거리 계산 |
|---|---|---|
| 확장 없음 | `document_chunk.embedding real[]` | `nyan_cosine_distance()` (마이그레이션 0013) |
| 확장 있음 | 같음 | `embedding_v <=> ...` + HNSW 색인 |

원본은 언제나 `real[]` 다. 확장이 켜져 있으면 같은 값을 `vector(1024)` 칼럼으로 **옮겨 둘 뿐**이다.
그래서 확장을 나중에 켜도 **다시 임베딩하지 않는다** (`syncVectorColumn`).

```powershell
pwsh scripts/enable-vector.ps1          # postgres 비밀번호를 물어본다
pwsh scripts/enable-vector.ps1 -Env prod
```

확장 파일 자체가 없으면 `infra/install-pgvector.ps1` 이 먼저다 (관리자 · PostgreSQL 재시작).

## 한국어에는 형태소 분석기가 없다

`to_tsvector('simple', ...)` 은 띄어쓰기로만 쪼갠다. 그래서

> "배추 절이는 시간"

으로는 "배추**를** … **여섯**시간" 을 못 찾는다 — 조사가 붙어 토큰이 다르다.
그래서 어휘 검색은 **낱말마다 부분 일치**를 보고, **몇 낱말이 들어 있는지**를 첫 번째 순위로 쓴다.
`packages/db/src/queries/search.ts` 가 문서 단위에서 쓰는 것과 같은 논리다.

### 왜 점수를 더하지 않고 순위를 합치는가 (RRF)

`ts_rank` 와 코사인 거리는 **단위가 다르다.** 가중치를 손으로 맞추면 문서가 늘 때마다 다시 맞춰야 한다.
RRF 는 단위를 버리고 순위만 본다:

```
점수 = 1/(60 + 어휘순위) + 1/(60 + 벡터순위)
```

손볼 것이 없고, 한쪽 길로만 들어온 근거도 자연스럽게 섞인다.

**한 문서에서는 최대 두 토막**만 가져온다 (`perDocument`). 긴 문서 하나가 근거 자리를 다 차지하면
같은 이야기를 여섯 번 읽는 셈이라 얻는 것이 없다.

## 근거가 답보다 먼저 뜬다

`/api/ai/ask` 는 SSE 로 `sources` 를 **먼저** 보내고 그다음에 답을 흘려보낸다.
답을 기다리는 동안에도 어느 문서에서 나온 이야기인지 알 수 있고, 답이 시원찮으면 그냥 문서로 가면 된다.

번호(`[1]`)를 누르면 **그 블록까지** 간다. 그래서 토막이 `block_id` 를 물고 있다 —
평문만으로는 줄을 가리킬 수 없다. 주소는 `/d/<문서>#block-<블록>` 이고,
`components/jump-to-block.tsx` 가 블록이 생기는 것을 지켜보다가(MutationObserver) 데려가서 잠깐 표시한다.
에디터가 뜨는 데 몇 초 걸리므로 **정해진 시간만 기다리지 않는다.**

근거가 하나도 없으면 **모델을 부르지 않는다.** 지어낼 여지를 주지 않는 것이 옳다.

## 권한은 한 곳에서 끝난다

```ts
const allowed = await readableDocumentIds(viewer.userId);
const passages = await retrievePassages({ documentIds: [...allowed], ... });
```

`documentIds` 밖의 문서는 **어느 길로도** 들어오지 못한다 — 어휘 검색도 벡터 검색도 같은 `where` 를 쓴다.
프롬프트에 들어가는 글이 전부 그 목록에서 나온 것이므로, 모델이 남의 문서를 인용할 방법이 없다.
목록이 비면 아무것도 돌려주지 않는다 (열린 기본값을 두지 않는다).

모래상자로 간 문서는 색인에서 **지운다.** 지운 글이 근거로 나오면 안 된다.

---

## 제목·태그 추천은 수락해야 반영된다

모델이 사람이 쓴 제목을 조용히 바꾸면, 사람은 자기 제목이 왜 사라졌는지 알 수 없다.
그래서 제안은 `document_suggestion` 에서 **문서 밖에 기다리고**, 누르면 그때 옮겨 간다.
제목만 받고 태그는 버릴 수도 있다.

추천은 **쓸모가 있을 때만** 줄에 세운다 — 제목이 없거나 태그가 하나도 없고, 본문이 200자는 될 때
(`enqueueSuggestIfUseful`). 저장마다 모델을 부르면 GPU 가 종일 돈다.

---

## 모델

| | | |
|---|---|---|
| 임베딩 | `bge-m3` | 1024차원 · 1.2GB. 한국어를 잘하는 다국어 모델 |
| 답 | `exaone3.5:2.4b` | M5 에서 고른 것 그대로 |

임베딩은 **길이를 1 로 맞춰서** 저장한다. 그래야 코사인 거리가 흔들리지 않는다.

**임베딩에는 클라우드 폴백이 없다.** 생성(`streamCompletion`)과 다른 점이다 —
임베딩은 문서 본문을 통째로 밖으로 보내는 일이고, 그건 이 집 서버를 만든 이유와 반대다.
게임 중이면 기다린다.

`AI_EMBED_MODEL` 을 바꾸면 차원이 달라져 **색인을 전부 다시 만들어야 한다.**
게이트웨이가 차원이 다르면 그 자리에서 거절한다.

## 돌려 보기

```powershell
pnpm worker                                  # 계속 돈다 (자동 시작에도 등록돼 있다)
pnpm worker:once                             # 큐를 비우고 끝난다
pnpm --filter @nyanotion/worker smoke        # 34개 점검
```

확인한 것 (`smoke`, 34개):

- 절(제목)마다 토막이 나뉘고 토막마다 블록 id 를 문다
- 안 바뀐 문서는 다시 임베딩하지 않고, **고친 토막만** 다시 한다
- 문서가 짧아지면 남은 뒷토막을 치운다
- 글자가 안 겹치는 질문("겨울에 담그는 저장 음식")도 뜻으로 찾는다
- 임베딩 없이도(게임 중) 어휘 검색은 된다
- **남의 비공개 문서는 뜻이 정확히 맞아떨어져도 근거로 나오지 않는다**
- 같은 문서를 두 번 적어도 큐는 한 줄, 집어 간 일은 두 번 안 잡힌다
- 수락하기 전에는 문서가 안 바뀌고, 제목만 받으면 태그는 만들어지지 않는다

브라우저로 확인한 것 (2026-09-27, 운영과 같은 빌드로 3200 포트에 띄워서):

- 문서를 쓰고 → 색인되고 → `/ask` 에서 "김장할 때 배추를 얼마나 절였지" 에
  **"배추는 소금물에 여섯 시간 절였습니다. [1], [2], [3]"** 이라고 답했다
- 근거가 답보다 먼저 떴고, 번호를 누르니 **그 줄**로 가서 표시됐다

## 아직 안 한 것

- 워커가 하나뿐이다. `for update skip locked` 로 여럿을 대비해 뒀지만 띄워 보지는 않았다
- 답을 나중에 다시 볼 수 없다 (질문 기록을 남기지 않는다)
- 색인이 얼마나 밀렸는지 화면에 안 보인다 (`indexQueueAction` 은 있다)
