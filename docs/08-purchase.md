# 08 — 구매: 적어 두기 → 값 찾기 → 승인 → 장바구니

살 것을 적어 두면 값을 찾아 오고, **가족 중 누구든 한 명이 승인**해야 실제로 산다.
돈이 나가는 기능이라 다른 어느 곳보다 "멈출 자리"를 많이 뒀다.

```
 적어 둠 ──▶ 찾는 중 ──▶ 승인 기다림 ──▶ 승인됨 ──▶ 장바구니에 담김 ──▶ 주문함 ──▶ 받음
 listed     searching     proposed       approved     carted          ordered   done
    ▲                         │             │
    └───── 안 사기로 함 ◀──────┴─── 5분 유예 안에 취소 ───┘
           rejected
```

사람이 하는 일은 셋뿐이다 — **적기 · 승인 · 결제 버튼 누르기.**

---

## 멈출 자리 네 군데

이 기능에서 가장 중요한 설계는 "무엇을 자동으로 하느냐"가 아니라 **"어디서 멈추느냐"** 다.

1. **한도(`maxPriceKrw`)** — 넘으면 승인 단추가 아예 막힌다. 에이전트도 넘는 후보는 올리지 않는다.
2. **승인** — 사람이 누르기 전에는 아무 일도 없다. 알림은 가족 **모두**에게 가고, 한 명이 답하면
   나머지 기기의 알림이 같은 `tag` 로 대체된다.
3. **5분 유예(`cancellableUntil`)** — 승인해도 곧바로 사지 않는다. 잘못 누른 것을 되돌릴 틈.
4. **결제 버튼** — 에이전트는 **절대 누르지 않는다.** 장바구니에 담고 결제 화면을 열어 둘 뿐이다.

넷째가 이 설계의 핵심이다. 선택자 하나만 잘못 읽어도 엉뚱한 것을 사 버리는데, 그건 되돌릴 수
없다. 마지막 한 번을 사람이 누르면 그 사고가 **구조적으로 불가능**해진다.
`apps/agent/src/cart.ts` 에 두 번째 문(`NEVER_CLICK`)까지 둔 이유다 —
선택자를 넓히다 실수로 결제 단추를 잡아도 글자를 보고 물러난다.

---

## 어디서 값을 찾나

| | 방법 | 왜 |
|---|---|---|
| 네이버 | **공식 검색 API** | 무료·합법·안 깨진다. 하루 2만 5천 건이면 집에서 넘친다 |
| 쿠팡 | 사람이 로그인해 둔 브라우저 | 공식 API 가 없다. **막히면 물러난다** |

### 네이버 키 넣기 (권장)

없어도 돌지만, 있으면 대부분의 "못 찾음"이 사라진다.

1. https://developers.naver.com → 애플리케이션 등록
2. 사용 API 에서 **검색** 을 고른다
3. 나온 Client ID · Secret 을 그 환경 설정에 넣는다:

```
NAVER_CLIENT_ID=...
NAVER_CLIENT_SECRET=...
```

배송비는 이 API 가 주지 않는다 — 0 으로 들어가므로 화면의 합계는 **상품값 기준**이다.

### 쿠팡은 자주 막힌다

실제로 확인했다: 로그인 없이 헤드리스로 열면 곧바로 차단 화면이 뜬다. 그래서 에이전트는

- 사람이 한 번 로그인해 둔 **지속 프로필**을 그대로 쓰고 (`pnpm agent:login`)
- 창을 띄워 둔 채 돌고 (사람이 보고 있어야 맡길 수 있다)
- **막히면 그대로 물러난다.** 우회하지 않는다 — 그건 선을 넘는 일이고, 네이버만으로도 후보는 나온다

차단됐거나 화면 구조가 바뀌면 그 이유를 살 것의 메모에 적어 준다. 그때는
**후보를 손으로 넣으면 된다** (`후보 직접 넣기`) — 승인 대기 중에도 더할 수 있다.

---

## 에이전트 돌리기

집 컴퓨터에서 도는 일꾼이다. 웹 서버와 별개 프로세스다.

```powershell
pnpm agent:login    # 한 번만 — 창이 열리면 쿠팡·네이버에 로그인하고 Ctrl+C
pnpm agent          # 계속 돌린다
pnpm agent:once     # 한 바퀴만
```

**브라우저 프로필은 저장소 밖에 둔다** (기본 `~/.nyanotion/browser-profile`).
그 안에 로그인 쿠키가 들어 있어서, 저장소 안에 두면 실수로 커밋될 여지가 생긴다.
비밀번호는 우리가 받지도, 저장하지도 않는다 — 사람이 브라우저에 직접 로그인한다.

에이전트는 사람이 아니라 이 집 컴퓨터의 프로세스라 space 권한이 성립하지 않는다.
대신 **무엇을 할 수 있는지가 상태로 묶여 있다** — `searching` 인 것만 찾고,
유예가 끝난 주문만 담는다 (`listItemsForAgent` · `ordersReadyToPlace`).

---

## 기록은 살 것보다 오래 산다

"구매 히스토리가 남는다"가 요구사항의 절반이다. 그래서 `purchase_order` 는
가리키는 것들이 전부 끊어질 수 있게 두고, 필요한 값은 복사해 둔다
(`spaceId` · `itemTitle` · `source` · `title` · `url` · `totalKrw`).

살 것을 목록에서 빼도, 후보가 지워져도, 문서를 버려도 **"언제 무엇을 얼마에 샀는가"는 남는다.**
취소해도 줄은 남고 `cancelledAt` 이 찬다.

> 처음(0011)에는 `item_id` 가 cascade 라 살 것을 빼면 기록까지 사라졌다. 0012 에서 고쳤다.

---

## 약관에 대해

쿠팡·네이버 모두 자동 접속을 약관으로 제한한다. 이 설계는 그 점을 알고 만들었다:

- 네이버는 **공식 API** 만 쓴다 (허용된 길)
- 쿠팡은 사람이 로그인한 브라우저에서, 사람이 볼 수 있는 화면을, 사람이 하는 속도로 본다.
  **막으면 물러난다** — 우회 장치를 넣지 않았다
- **결제는 사람이 한다.** 자동 주문·자동 결제는 하지 않는다

가족이 쓰는 집 서버, 본인 계정, 본인 장보기라는 전제다. 이 범위를 넘기면 계정이 막힐 수 있고,
그건 되돌리기 어렵다.

## 확인하기

```powershell
pnpm --filter @nyanotion/agent smoke      # 응답 해석 · 합계 정렬 · 결제 금지 규칙
node apps/web/scripts/e2e-buy.mjs          # 적기 → 후보 → 승인 → 취소 → 히스토리
```

쿠팡 쪽은 실제 화면이 있어야 해서 스모크로 못 본다. `pnpm agent:once` 로 직접 돌려 보는 게 유일한 길이다.
